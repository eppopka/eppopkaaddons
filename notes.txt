WHAT WENT WRONG IN THE FIRST DELIVERY
-------------------------------------
The latest public commit has both the new and the old PetDisplay.kt and
ShitterList.kt files. It also still has LbTimer.kt. The earlier ZIP contained
only the replacement src tree, without sufficient deletion instructions.
Merging that ZIP leaves the old source files behind.
ClassGraphInitializer.registerFeatures() discovers every Feature subclass
under features.impl, so different packages are different registered objects,
even if they have identical display/config names. This causes duplicate GUI
entries, duplicate pet HUD elements, and potentially duplicate event handlers
or /sl command registration. ConfigManager resolves features/HUDs by name,
which becomes ambiguous with duplicates.

The moved general/PetDisplay.kt also still explicitly declared
"override val category = CategoryType.VISUAL". That contradicted its folder.
The spatial GUI had an independent class-name allowlist, so GUI category
assignment and Feature.category could disagree.

PET OVERLAY — CURRENT RENDER FIX
-------------------------------
Actual object/class name is PetDisplay; display name is "Pet Overlay".
No explicit category override now; its general folder determines Global.

Previous renderer: utils/render/ItemRenderer.kt implements a custom full-screen
picture-in-picture batch. It copies the HUD pose and separately multiplies
item translations by window GUI scale. Its supplied x/y are NOT simply an
item center: renderToTexture adds +8 to both coordinates before item scaling.
The earlier comment claiming that x/y were centered was incorrect.
Changing one y value in this custom path was not sufficient evidence of a fix.

This delivery bypasses that custom renderer for the pet portrait only:
  pushMatrix -> translate(11, 8) -> scale(1.55, 1.55)
  -> ctx.item(activePetStack, 0, 0) -> popMatrix in finally.
Minecraft 26.1.2 GuiGraphicsExtractor.item was inspected with javap. It copies
its current Matrix3x2f pose and scissor into GuiItemRenderState. The native
16x16 item therefore shares the card's HUD, resolution and GUI transforms.
Local nominal portrait box: x=11..35.8, y=8..32.8. XP bar starts at y=36;
name/level text begins at x=51. This box fits both compact and full cards.
The shared ItemRenderer was NOT changed, to avoid affecting other callers.
Do not compensate for screen coordinates/window scale inside this local draw.

HUD transforms: ui/utils/Resolution.kt applies a 960x540 reference scaling;
ui/hud/HudElement.kt adds saved position and HUD scale before drawing.
Native rendering should inherit both transforms exactly once.
Pet menu ItemStack is copied into activePetStack, retaining the actual skull
texture/components rather than hardcoding a pet image.

PET XP — RETAINED BEHAVIOR AND HONEST LIMITATIONS
------------------------------------------------
PetDisplay reads name, rarity, level and numeric current/required XP from the
Pets menu lore, caches visited pet stacks, and recognizes summon/autopet chat.
Without first opening the Pets menu, a chat-selected uncached pet has no item
or XP baseline. Open /pets with the active pet visible after joining.
Actionbar skill gains are added to the estimated pet XP and level progress.
This is NOT authoritative pet XP: skill mismatch penalties, Taming, pet items,
special pets, repeated actionbar messages, etc. are not fully modeled.
The numeric XP regex currently does not parse suffixes such as k/M. The generic
level table/200-level fallback is also not a complete model of every pet.
XP cache can be stale after swaps; XP samples are session-local.
Do not tell the user that exact Hypixel XP has been validated in-game.
A proper future XP fix needs real server lore/actionbar examples, pet bonuses,
and repeated-message handling; avoid inventing pet-specific rules.
